# Project rules informed by general practice

These are PragMattie PMO's own working rules, written in our own words. They were informed by
general practice: general project practice, AI governance practice, and AI project practice. They are not published text and not a summary of those works. published has not reviewed
or endorsed this project. The references say where a reader with their own copy can look.

Every number in `policies/` is our own choice.

## Keeping this file

A person with a licensed copy writes and changes this file. Agents follow it and never edit it. If
a task needs a rule that isn't here, say so in your summary rather than working from memory.

Each rule says what this product does, briefly, in the order that suits this product. Never add
sentences, tables, figures or lists from a source. Before merging a change, check it for wording
shared with the sources. The source texts never enter this repository, its workflows or an agent's
instructions.

## People decide

- **R1.** An agent's output is a proposal. A named person makes any decision with real
  consequences, and the record shows who. (AI Standard 1.6.3, 3.5.3)
- **R2.** A person can pause, change or overrule anything an agent is doing, at any point.
  (AI Standard 3.5.3)
- **R3.** What makes a person step in, and who it goes to, is agreed in advance and written in
  `policies/`, not left to an agent's judgement. (AI Standard 1.6.3, 3.5.3)
- **R4.** Every agent has written limits: what it may do alone and when it must stop and ask.
- **R5.** Every agent records what it did, what it decided and the data it used.

## Security

- **R6.** Only authorized people reach data and functions, data is protected when stored and when
  moving, and security gets reviewed on a schedule. (AI Standard 3.3.4)

## Risk

- **R7.** Risk appetite is stated as a measurable threshold for each project objective.
- **R8.** Probability and impact levels are defined for the project and apply to threats and
  opportunities alike.
- **R9.** Some risks don't fit the scales, such as ethical, reputational or morale risks. An agent
  never scores these alone; they go to a person.
- **R10.** The risk register records AI-specific threats and opportunities as well as ordinary
  project risks. (AI Standard 3.5.1)

## AI projects

- **R11.** An AI project ends AI project Phase I with a green, yellow or red readiness call. Yellow
  needs an action with an owner and a date; red stops work until it is fixed.

## Words

- **R12.** Use the names in `docs/standards-map.yaml` for stages, domains, AI
  Standard sections and AI project stages. Use sponsor, project manager and risk register for those
  things, not synonyms.
